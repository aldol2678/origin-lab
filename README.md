# Origin Lab | 기원의 실험실

An experimental evolution and ecosystem sandbox web game.

**Status:** Early prototype / Work in progress

## v0.2 실행 및 개발

첫 생명의 기원을 탐색한 뒤, **다세포와 얕은 바다**에서 새로운 생물과 기존 미생물의 관계를 실험하는 독립 웹게임입니다.

## 실행

`origin-lab-v0.2.html`을 최신 브라우저에서 여세요. HTML 안에 코드·데이터·스타일·그림이 모두 들어 있으며, 게임 실행에 설치, 계정, 외부 서버, 유료 서비스가 필요하지 않습니다.

파일 열기를 제한하는 환경에서는 폴더에서 다음 명령을 실행한 뒤 `http://localhost:8000/origin-lab-v0.2.html`을 여세요.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

이번 검증 환경의 Chromium 관리 정책은 `file://` 접근을 차단했습니다. 따라서 **더블클릭 실행 자체의 검증은 BLOCKED**입니다. 로컬 HTTP 실행과 외부 네트워크를 차단한 단일 HTML 실행은 검증했습니다. 실제 휴대폰과 다른 브라우저 검증은 UNKNOWN입니다.

## 플레이

- **실험실**: 재료 두 개를 조합합니다. 재료는 사라지지 않으며 조합은 무료입니다.
- **세계**: 생물을 배치하고 먹이, 산소, 영양분과 개체 수를 살펴봅니다.
- **진화**: 연구, 첫 장의 세 조건 실험, 두 번째 장의 빛·물 교환 실험을 합니다.
- **기록**: 쉬운 설명과 과학 설명, 도감, 실험 로그, JSON 가져오기/내보내기를 봅니다.

첫 장을 마쳤거나 이전 저장에 환생 기록이 있으면 **진화 → 두 번째 장 탐험하기**로 바로 이어집니다. 환생할 필요가 없습니다. `연안 환경 + 물`로 조간대를 발견하고 `세포막 + 연안 군체`에서 세포의 협력을 탐색하세요. 발견한 생물을 조간대에 보충한 뒤 밝음과 그늘에서 각각 기록해 보세요. 무료 보충은 조간대의 관찰 준비 기능이며 재화를 주지 않습니다.

## 변경 사항

- 저장 정본을 `originLab.save.v3`로 분리했습니다. 구버전 키는 최초 이전 때만 읽으며 쓰지 않습니다.
- v1·v2 원본을 읽기 검증한 백업으로 보관합니다. 서로 다른 저장은 점수로 합치지 않고 복구 선택을 요청합니다.
- 두 창의 저장 충돌, 손상된 저장, 상위 스키마, 저장 공간 오류에서는 정본 덮어쓰기를 막고 상태 표시줄에 알립니다.
- 조합 **24 → 34**, 도감 **30 → 42**, 생물 **6 → 9**, 서식지 **2 → 3**, 관찰 **2 → 4**.
- 첫 장의 도감·영구 연구·최종 실험 측정값과 장 해금을 보존합니다. 첫 장 재시작 보상 +3은 한 번만 받고, 새 관찰 성취 두 개에서 각각 +2를 받습니다. 기존 재화는 회수하지 않습니다.
- 기존 첫 장의 생산 계수와 조합은 유지했습니다. 첫 장 엔딩과 ‘여기서 마치기’도 유지합니다.

## 저장 이전과 복구

1. 같은 브라우저·같은 저장 영역에서 열면 기존 저장을 확인합니다. v1/v2가 다르면 자동 선택하지 않습니다.
2. 화면 위 **백업·복구**에서 발견 수, 기원 데이터, 환생 수, 장 상태를 비교하고 원하는 기록을 선택합니다. 한 번 더 확인한 뒤 교체합니다.
3. JSON 가져오기와 복구는 현재 메모리 상태, 현재 정본, 저장 이력을 먼저 백업합니다. 취소하면 교체하지 않습니다.
4. 충돌 시 플레이와 자동 저장을 일시 중지합니다. 두 창을 닫기 전에 필요한 JSON을 보관하고, 한 창에서 사용할 기록을 선택하세요.
5. 브라우저나 파일 경로가 다르면 저장 공간도 다를 수 있습니다. **자동 승계를 보장하지 않습니다.** 기존 v0.1.1의 JSON 내보내기 → v0.2의 가져오기를 사용하세요. v0.1 원본 파일에는 내보내기가 없으므로 다른 저장 영역의 기록은 자동으로 찾을 수 없습니다.

화면 위 JSON 내보내기는 현재 플레이 상태를, 복구 창의 ‘원본 JSON’은 선택한 백업의 원문을 내려받습니다. 브라우저 저장을 사용할 수 없는 경우에도 현재 플레이 상태를 JSON으로 보관할 수 있습니다. 자동 저장은 10초마다 및 주요 행동·창을 닫을 때 수행됩니다. 브라우저 강제 종료 직전의 미저장 변화까지 보장하지는 않습니다.

## 개발과 테스트

Node.js 24에서 검증했습니다. 게임 자체는 Node.js 없이 실행됩니다.

```sh
npm ci
npx playwright install chromium
npm run build
npm test
npm run test:browser
```

브라우저 테스트는 Playwright의 Chromium을 사용합니다. 설치된 브라우저를 쓰려면 `CHROMIUM_PATH`를 지정하세요. v0.2 소스 ZIP의 JavaScript·데이터·테스트를 그대로 기준선으로 편입했습니다. v0.2 당시 원본 TypeScript가 아닌 번들에서 추출한 JavaScript라는 이력은 유지합니다.

- `baseline/`: 회귀 테스트에 필요한 기존 HTML과 번들의 포맷 사본
- `src/game.js`: 복원한 번들에 적용한 엔진·UI 수정 (원래의 축약 식별자가 일부 남아 있음)
- `src/persistence.js`: v3 정본·이력·백업·충돌 처리
- `src/chapter.js`: 새 장 데이터·생태계 연결·관찰·복구 UI
- `src/style.css`, `src/shell.html`: 단일 파일 빌드 입력
- `data/catalog.json`: 전체 콘텐츠의 검토용 스냅샷
- `tests/`: 결함 재현, 엔진·저장 단위/통합 테스트, Playwright UI 테스트
- `docs/`: 설계 결정, 콘텐츠 목록, 밸런스 비교, 저장 형식
- `qa/V02-BASELINE.md`: 새 환경의 기준선 검증 결과
- `qa/screenshots/`: 모바일 너비별·PC·저장 복구 화면

공개 저장소는 WIP 검토용이며 코드 라이선스는 아직 결정되지 않았습니다. LICENSE 또는 제3자 폰트·에셋은 포함하지 않습니다. `?debug=1`은 테스트용 내부 상태 접근을 켭니다. 일반 플레이 주소에는 필요하지 않습니다.
